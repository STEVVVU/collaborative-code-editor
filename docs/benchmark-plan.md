# Frozen notebook benchmark v1

Claim to test: disk-backed notebook protocol throughput, scheduled edit-to-all-client convergence latency and reconnect catch-up under bounded concurrent use. This does not measure Monaco paint or browser rendering. No speedup claim is accepted without matched repeated before/after runs and a separate source-mapped profile.

Run on an otherwise idle Ubuntu hosted runner with Node24, `npm ci` and `npm run build:packages`. Use `node tools/benchmark-notebooks.mjs --smoke` for a correctness-only lifecycle check. The full command is `node tools/benchmark-notebooks.mjs`; `--profile` is a separate unreported CPU-profile workload. Outputs are ignored under `.audit/benchmarks/`. `BENCH_OUTPUT` selects a fresh evidence directory.

The frozen full matrix is 2/8/32 clients, 1/16/48 KiB initial source, 1/10/50 scheduled aggregate edits per second, ten seconds per cell and five repeats with reversed client-count order on alternating repeats. Each edit appends a unique nine-byte marker. One real update warms all peers before the clock. Every repeat adds an eight-client reconnect case; the last peer disconnects for the middle third and authenticates again to catch up. A final120-second eight-client10 edits/s stability case retains every marker below the65,536-character product limit. Fresh service process, SQLite database and notebook per cell avoid answer/cache carryover. SQLite uses the shipped DELETE journal and full-snapshot update path unchanged.

Measure arrival-relative ack and last-peer p50/p95/p99/min/max, raw per-edit delivery samples, generator arrival lateness, unacknowledged backlog, WebSocket buffered bytes, child CPU/RSS/resource snapshots and generator CPU/RSS/event-loop delay. Offers stay on an absolute clock, so generator and service queue delay remain in latency. Count every offer, acknowledgment, convergence, rejection, unexpected close and timeout. Drain30 seconds without creating additional offers. Assert exact peer/persisted equality and every unique marker. Failed cells and partial campaign evidence survive cleanup and exit nonzero. The campaign has a45-minute hard ceiling and requires10 GiB free.

Comparisons use identical workload, OS/runtime and warmup, five paired alternating campaigns or matched cells. Report median and range across repeats, tails and errors, plus raw sample hashes. Inspect the separate child profile and CPU/RSS, generator lag and documented payload-byte arithmetic before attributing a limiter. The generator checks marker membership across all prior updates on each received snapshot. This correctness work can dominate32-client cells. Profile the generator separately with `node --cpu-prof --cpu-prof-dir=.audit/benchmarks tools/benchmark-notebooks.mjs --profile`; this also profiles the service child. A saturated generator makes the server-capacity conclusion inconclusive. The full-snapshot protocol and single-threaded disk writes are hypotheses to test, not diagnosed bottlenecks. The fixed data-size sweep is owned synthetic source and carries no third-party dataset license.
